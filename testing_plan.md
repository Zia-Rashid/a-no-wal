# a'no:wal testing plan

How the interpreter (`anwl`) is tested. Each layer below matches a stage in `notes.md` §2
and a section of `semantics.md`. Tests for a stage are written **with** that stage, not
after it.

---

## 1. Tools

| Tool | Used for |
|---|---|
| **dune** (`dune test`) | runs everything |
| **ppx_expect** | OCaml-level tests with the expected output written inline; `dune promote` accepts new output after review |
| **QCheck** | property tests: random inputs, with failing cases shrunk to a minimal example |
| **golden runner** | a small dune rule: run `anwl` on `x.t` and diff the output against `x.expected` |

dune's built-in cram tests use the `.t` extension, so they're switched off with
`(cram disable)` in `dune-project`. Otherwise every `.t` program would be run as a cram
test.

**Commands:**
```
dune test                  run all tests
dune test test/types       run one layer
dune promote               accept changed expected output (review the diff first)
```

---

## 2. Layout

```
test/
  golden/         runner.exe + gen.exe, shared by every golden directory
  lex/            ppx_expect: source text → token table; also source positions, diagnostics
    golden/       *.t + *.expected   (`--dump=tokens`, lexical errors through the CLI)
  parse/          ppx_expect: parser, printers, placeholder rewrite, parent links
    golden/       *.t + *.expected   (`--dump=ast`, syntax errors through the CLI)
  names/          *.t + *.expected   (binder columns, fill-ins, module errors)
  types/
    pass/         *.t + *.expected   (inferred type of each definition)
    fail/         *.t + *.expected   (exact error text)
  core/           *.t + *.expected   (--dump=core output)
  run/            *.t + *.expected   (output and exit code)
  errors/         *.t + *.expected   (runtime error message + trace)
  fuzz/           QCheck: fuzz_lex.ml, fuzz_parse.ml (crashes + round trip)
bench/            performance runs, not part of `dune test`
```

**Golden file conventions:**
- `x.t` is the program. `x.expected` is its exact output: stdout, then stderr, then
  `[exit N]` when the exit code isn't 0.
- The first line of `x.t` may give the command and flags as a comment:
  `%% args: check --dump=core --annot=types`. Without it the command is `run`.
- Every golden directory has the same `dune` file (copy `test/lex/golden/dune`, fix the
  `../` depth). Its rules live in `dune.inc`, generated by `test/golden/gen.exe`.
- **Adding a test:** write `x.t`, run `dune test`, then `dune promote`. The first promote
  regenerates `dune.inc`; the second creates `x.expected`. Read it before keeping it.
- **One behaviour per file**, named after it, e.g. `run/int_promotes_at_2_30.t`, so a
  failure explains itself.

## 3. Layers

### 3.1 Lexer (`test/lex`)
- **Numbers**, every case in notes 1.12:
  - `255 0xff 0xFF 0b1111_1111` lex as the same value;
  - each separator error (`0x_ff 1__0 10_`) is rejected;
  - `007` is decimal;
  - `1e9` and `1.5e-3` are `kl`; `1.` and `.5` are errors;
  - `0..5` lexes as three tokens.
- **Strings:**
  - every escape, and `\u{…}`;
  - NFC normalisation: a composed and a decomposed `á` give the same token text.
- **Comments:** `%%` vs `%`.
- **Touching `>`:** the flag is set for `>>` and clear for `> >`.
- **Keywords vs identifiers:** every keyword; `_`, `_0`, `_12`; an identifier can't start
  with `_`.
- **Statement ends:** a newline that ends a statement vs one that continues it (after an
  operator, `,`, `(`, `[`, an unclosed `<`); a newline before `(` always ends one.

### 3.2 Parser (`test/parse`)
- **Round-trip property (QCheck, `test/fuzz/fuzz_parse.ml`):** random programs are
  generated as fully parenthesised source, parsed, printed with minimal parentheses and
  parsed again; both trees must match.
- **Precedence:** one test per row of `grammar.md` §3. Cover:
  - associativity (`a - b - c`, `a ? b : c ? d : e`, `1 << 2 << 3`);
  - non-associative errors (`0..1..2`);
  - comparison chains: `0 <= i < n` and `a == b == c` parse as one chain; `a < b > c`,
    `a != b != c` and `a != b < c` are errors with the `&&` hint; `(a < b) < c` stays a
    type error;
  - `-f(x)`, `-x.sz`, `0..n by k+1`.
- **Disambiguation:** at least one test per rule in `grammar.md` §4:
  - declaration vs expression;
  - the `x? y: z` tie-break both ways;
  - `:` / `=` / `::`;
  - `<` as object vs less-than;
  - `>` inside objects;
  - alias vs ADT;
  - pattern binding vs constructor;
  - `ahket` with and without an operand.
- **Forms:** every IIFE form; quotes with `$`; `cast<T?>`; `export` / `use`.
- **Recovery:** a file with 3 separate syntax errors reports exactly 3 errors, in order.
  A statement with two problems reports only one.

### 3.3 Placeholders (`test/parse/test_placeholder.ml`)
- `_` in a `katsa` arm body is the matched value; inside a nested `otala` it's a function again.
- Every row of the boundary table in notes 1.11, checked on the rewritten tree
  (`--dump=ast` shows it too).
- Each placeholder error: `_0 + _2`, mixed `_` and `_1`, `_: 5`.
- The "unused function value" warning.

### 3.4 Names (`test/names`)
- **Shadowing vs reassignment:** the `f()` example from notes 1.15 prints `3`; after
  `x: 10`, `f` still sees the old `x`.
- **`::`:** it's non-recursive; the `log` wrapper calls the previous `log`.
- **Top level:**
  - hoisting (mutual recursion in any order);
  - use before definition is a compile error when direct, a runtime error when through a
    function;
  - a name defined twice is an error;
  - the REPL redefinition exception.
- **Fill-in:**
  - a match is found;
  - none is found (error text);
  - the nearest match has the wrong type (error, no further search);
  - the callee is a function value (arity error);
  - `--fills` output.
- **Modules:**
  - `export` / `use` / `as`;
  - using a private name is an error;
  - a `use` cycle is an error;
  - a clash with a top-level name is an error.
- **Namespaces:** duplicate constructor names across types; a type name used as a
  variable.

### 3.5 Types (`test/types`)
Every rule in `semantics.md` §5 gets one passing test and one failing test, and failing
tests check the **exact** message text (`x was __, we expected __.`).
- **Core rules:** each of the 13, including n-ary arity mismatch, rows (`getx` on objects
  with extra fields), `letrec` monomorphic inside / polymorphic outside, and a reassigned
  binding staying monomorphic.
- **Option insertion:**
  - `int? a: 5`;
  - a parameter of type `int?`;
  - the unannotated `c ? 5 : nil` error;
  - `int??` gets only one `some` inserted.
- **Operator table:** every row, plus the unresolved defaults (`int`, or an error for
  `.sz` / `e[i]`).
- **Casts:** every row of the cast table, `cast<T?>`, and a cast that isn't defined.
- **`void`:** each forbidden position; each allowed position; `map(xs, print)`.
- **Aliases:** transparency; a recursive alias is an error; alias vs ADT.
- **Scoped type variables:** sharing in nested functions; shadowing with `otala<a>`.
- **`katsa`:**
  - a missing constructor (the list printed);
  - an unreachable arm (warning);
  - the typo-binds-everything warning;
  - the warning for a variable that hides a constructor.

### 3.6 Desugaring (`test/core`)
One `--dump=core` golden test per row of the surface → core table (`semantics.md` §3.1).
For chains, also a `test/run` test that a middle operand with a side effect (`0 < f() < 10`)
runs once, and that a false first link skips the rest.
These also fix the tree-printer format (notes 1.22) in place.

### 3.7 Evaluator (`test/run`)
- **Evaluation order:** `f(print("a"), print("b"))`, object field order, `&&`/`||`
  short-circuit.
- **Numbers:**
  - promotion just below and just above 2³⁰ and 2³¹;
  - canonical form (a big result that fits drops back to small, and `==` agrees);
  - 64-bit overflow error;
  - `7 / 2`, `7 / 2.0`;
  - the `%` table (`7.5 % 2`, `-7.5 % 2`);
  - mixed `int`/`kl` ordering;
  - shifts at their limits.
- **Strings:**
  - `"abc".sz == 3`, `"kátsaˀ".sz == 6`, `"ʌ́".sz == 1`;
  - `s[i]`, `for (c of s)`, slicing;
  - ordering;
  - `+` and `cc`.
- **Loops and ranges:** every example in notes 1.9, with its stated output as the
  expected file. Also `break`, `break e`, `ahket` inside a loop, nested loops, and
  reassigning an outer variable inside a loop.
- **Closures:** a captured and reassigned variable (box) vs a captured, never-reassigned
  one (copy); `letrec` mutual recursion; closures created in a loop.
- **IIFE forms**, including a recursive named one.
- **`katsa`:** nested patterns, literal patterns, arm order.
- **Stack:**
  - 10⁶ iterations of a tail-recursive loop run in constant stack;
  - a 10⁵-deep non-tail recursion completes (the frame stack grows; no host overflow).

### 3.8 Runtime errors (`test/errors`)
One test per error in `semantics.md` §9. Each checks the message, the full trace (function
names and positions) and exit code 2.

### 3.9 Metacircularity: the tower test
- Every program in `test/run` runs three ways: directly, through `eval`, and through
  `eval` running the evaluator running the program. **All three outputs must match.** The
  driver reuses the same `.expected` files, so no extra files are needed.
- Plus specific tests:
  - quote with and without `$`;
  - `eval` sees the caller's locals and globals;
  - `eval`'d code reassigns a caller local (box);
  - a `Dyn` check passing and failing;
  - `cast<int?>` on a `Dyn`;
  - fill-in at runtime under `eval`.

### 3.10 GC
- One test that allocates far more than the heap, to make sure collection happens at all
  and the output is still right.
- **Torture mode:** run the whole `test/run` suite with `--gc-verify` while collecting on
  every allocation. This is the fastest way to find a missing root.
- `--gc-verify` also checks header bits per generation: no grey after marking, no
  forwarded bits outside a minor collection, young ages 0-2, no free old block pointed to,
  and every old block holding a young pointer is in the remembered set.
- Write barrier: a young value written into a promoted box survives the next minor
  collection; a pointer moved from an unscanned block to a scanned one during a
  concurrent mark survives the sweep.
- Prim loop frame: `map` with a function that allocates enough to collect mid-loop gives
  the right result.
- `--gc-stats` output is checked only for shape (fields present), not exact numbers,
  since those change whenever the allocator does.

### 3.11 Fuzzing (`test/fuzz`)
- Random bytes → lexer and parser: may report errors, must **never** raise an OCaml
  exception or hang.
- Random token streams → parser: the same guarantee.
- **Later:** random well-typed programs, run both directly and through `eval`
  (differential testing).

### 3.12 Performance (`bench/`, not in `dune test`)
Step 8 of the plan: SoA vs a pointer tree on the same passes. Measure with `perf stat`
(cache misses), and time name resolution and type checking separately. Record the
results, with the machine and date, in `bench/RESULTS.md`.

---

## 4. Rules

- **A stage isn't done until its layer passes.** Write the tests first where practical
  (the expected output is often already in the notes).
- **Every bug fix adds a regression test** that fails before the fix.
- **Error text is part of the behaviour.** Tests compare messages exactly; change them
  deliberately, with `dune promote`.
- **No flaky inputs:** tests must not depend on hash order, timing or the environment.
  `read_line` tests feed fixed stdin.
- **Before accepting with `dune promote`,** review the diff; never promote blindly.
